# SUPsfactory — Sitemap Structure

> **Purpose:** This file documents the `/sitemap.xml` generation, its structural layout, how it interfaces with SEO configuration, and how to extend it for new pages or locales.

## 1. Sitemap Generation Overview

The `/sitemap.xml` is **dynamically generated** on every request from a single source of truth — `src/features/seo/seo.ts` (`PUBLIC_PATHS`). No static artifact is committed to the repo (generated by the Worker at runtime).

**Generation chain:**
```
seo.ts PUBLIC_PATHS  →  × locales (en, es)  →  hreflang alternates
       ↘                     ↘
         →  content registry      →  english-only content paths (no alternates)
                                           ↓
                                       /sitemap.xml (XML)
```

## 2. Structural Layout

### 2.1 Bilingual (`en`/`es`) Entries
- Every path listed in `PUBLIC_PATHS` × both locales
- Each entry includes `<url>` + `<lastmod>` + `<changefreq>` + `<priority>`
- **hreflang alternates**: each `<url>` may have one or more `<xhtml:link rel="alternate" hreflang="...">` pointing to the matching locale URL
- Example structure (simplified):

```xml
<url>
  <loc>https://supsfactory.com/</loc>
  <lastmod>2026-08-15</lastmod>
  <changefreq>monthly</changefreq>
  <priority>1.0</priority>
  <xhtml:link rel="alternate" hreflang="es" href="https://supsfactory.com/es/"/>
</url>
<url>
  <loc>https://supsfactory.com/es/</loc>
  <lastmod>2026-08-15</lastmod>
  <changefreq>monthly</changefreq>
  <priority>0.8</priority>
  <xhtml:link rel="alternate" hreflang="en" href="https://supsfactory.com/"/>
</url>
```

### 2.2 Content-Registry-Only (English-only) Entries
- Paths from `src/content/site/` registry that have **no bilingual route**
- These entries **do not** include hreflang alternates (they are English-only)
- Example:

```xml
<url>
  <loc>https://supsfactory.com/factory</loc>
  <lastmod>2026-06-01</lastmod>
  <changefreq>yearly</changefreq>
  <priority>0.5</priority>
</url>
```

### 2.3 Excluded Paths (forced 410 / disallow)
The edge gate (`src/features/seo/edge-gate.ts`) removes / 410s the following at the edge, **and** they are **explicitly excluded** from `PUBLIC_PATHS`:

- `/app`, `/admin`, `/*/admin`
- `/api`, `/docs`, `/waitlist`, `/changelog`
- Any legacy `/zh/*` URLs (redirected to `/es` equivalents)

These never appear in `/sitemap.xml` nor in `/robots.txt` sitemap reference.

## 3. SEO Configuration (`src/features/seo/seo.ts`)

The `PUBLIC_PATHS` constant is the **single source of truth** for sitemap inclusion. Its shape:

```typescript
export const PUBLIC_PATHS = {
  // Format: pathkey → { en: '/path', es: '/es/path' | null }
  home: { en: '/', es: '/es/' },
  products: { en: '/products', es: '/es/productos' },
  solutions: { en: '/solutions', es: '/es/soluciones' },
  // ... other mapped paths
  // content registry paths are injected separately from src/content/site/ registry
};
```

**How to add a new public page:**
1. Add an entry to `PUBLIC_PATHS` in `seo.ts` (with both `en` and `es` keys, or `null` if locale‑not‑applicable).
2. Ensure the route exists under `src/routes/{-$locale}/` (or is a content registry page).
3. Re‑run `pnpm build` — the sitemap will auto‑include the new URL on next request.

## 4. Robots.txt & Sitemap Reference

`/robots.txt` (generated from the same `seo.ts`) contains:

```
Sitemap: https://supsfactory.com/sitemap.xml
Sitemap: https://supsfactory.com/llms.txt
Sitemap: https://supsfactory.com/entity.json
Sitemap: https://supsfactory.com/rss.xml
```

The `/sitemap.xml` URL is listed here so crawlers discover it. No other sitemap‑related directives are needed.

## 5. Adding Multilingual Support (22‑language future)

The current sitemap structure is designed for **bilingual** (`en`/`es`) out of the box. To extend to an arbitrary number of languages in the future:

1. **Locale‑aware `PUBLIC_PATHS`**: change the value type from `{ en: string, es: string }` to a `Record<string, string>` keyed by locale code.
2. **Hreflang generation**: the sitemap generator will automatically produce `<xhtml:link hreflang="...">` for every registered locale.
3. **Content registry**: registry-only pages remain single-locale; they get no hreflang alternates but still appear as `<url>` entries.

## 6. Verification

After any change to `seo.ts` `PUBLIC_PATHS`:

```bash
# 1) Build
pnpm build

# 2) Request the live sitemap (or local dev server)
open http://localhost:3000/sitemap.xml

# 3) Validate XML (e.g., https://www.sitemaps.org/protocol.php)
# 4) Confirm new URLs appear; excluded paths (admin, /api, etc.) are absent
```
